# AIDT 技术栈与架构参考文档

> 版本：V2.0  
> 定位：AIDT 项目级生产技术栈、架构基线与离线交付规范  
> 冻结状态：**已冻结（FROZEN）**  
> 冻结日期：2026-10-30  
> 依据标准：`adminyc/AIBP-Tech-Standard-PSD` 中的《内网 AI 开发技术栈标准》v1.1  
> 变更规则：任何技术栈替换必须新增 ADR，说明原因、影响、迁移成本和回滚方案，经架构负责人批准后方可实施

## 🔒 技术栈冻结声明

AIDT 的统一生产技术栈冻结为：

> **.NET 10 + SQL Server 2025 + Vue 3 + Element Plus + Elsa Workflows + Hangfire + Garnet + Nginx + AiGateway + 离线部署包**

该组合用于：

- AIDT 初期框架搭建
- 本地目标模式 Demo
- 甲方单机内网部署
- 甲方复制代码后自行维护
- 断网环境构建、发布和恢复

该组合的主要目标不是追求最前沿技术，而是保证：

1. 所有 AIDT 项目使用同一套语言、数据库、前端和部署方式。
2. 甲方能够在没有互联网的环境中完成依赖恢复、构建和发布。
3. 同一套代码可以由不同开发和运维团队接手。
4. 甲方差异通过配置、数据库和独立适配器解决，不创建第二套技术栈。

> 企业标准文档当前仍为 v1.1 评审稿，但 AIDT 项目从本文冻结日期起按该技术组合实施。企业标准正式签字后，以签字版本为准；若签字版本与本文冲突，应通过 ADR 对齐。

## 🧭 一、总体判断

AIDT 的业务方向、对象模型和流程治理原则可行。现有 MVP 已证明：

- 业务对象可以独立于流程存在
- 流程实例可以引用主对象
- 待办、审批、退回、终止和条件跳转可以工作
- 任务动作可以写审计
- 数字员工可以有等级、范围、人工确认和运行记录

当前主要问题是生产成熟度，不是业务闭环可行性。

## 💻 二、当前验证技术栈

| 层 | 当前方案 |
|---|---|
| 运行时 | Node.js 24 |
| 后端 | Node.js 原生 HTTP |
| 数据库 | `node:sqlite` |
| 前端 | 原生 HTML/CSS/JavaScript 单页应用 |
| 测试 | Node 原生 API 测试 + Edge DevTools 浏览器测试 |
| 外部系统 | Mock provider |
| 数字员工 | 本地规则模拟，不调用大模型 |
| 部署 | Windows 本地进程一键启动 |

### 适用场景

- 业务概念验证
- 流程语义验证
- 交互原型演示
- 自动化测试样例
- 正式系统迁移基线

### 不适用场景

- 真实生产数据
- 多用户并发业务
- 正式 SSO 和权限隔离
- 法规级审计与电子签名
- 多组织、多工厂规模化运营
- 高可用和灾备

## 🏗️ 三、冻结后的生产架构

采用 Windows 单机内网部署、模块化单体、后台 Worker 和统一 AI 网关架构。第一阶段不使用微服务、消息中间件、Docker 或 Kubernetes。

```text
PC 管理端 / 专业工作台 / 一线移动端
                    │ HTTPS 443
                    ▼
               Nginx 唯一入口
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
   AIDT ASP.NET Core      AIDT Worker
   模块化单体应用          Hangfire / Outbox
          │                   │
          ├─────────┬─────────┤
          ▼         ▼         ▼
   SQL Server    Garnet    本地文件/NAS
      2025      缓存/锁    附件/证据/备份
          │
          ├── AiGateway :5100 ── Ollama / 本地模型
          │          └────────── Python AI 侧车（可选）
          │
          └── Adapter Projects
              U9 / ERP / DCS / WMS / LIMS / 钉钉
```

部署边界：

- Windows Server 2019 及以上。
- 所有内部服务只监听 `127.0.0.1`。
- Nginx 是唯一对外入口。
- 业务应用和 Worker 以 Windows 服务运行。
- SQL Server 不对内网用户直接开放。
- 应用不使用 Docker Desktop、Kubernetes或外部消息队列。
- 甲方差异通过环境配置、数据库和独立 Adapter 项目实现。

## 🧰 四、冻结技术栈

### 4.1 核心组合

| 层 | 冻结技术 | 使用方式 |
|---|---|---|
| 操作系统 | Windows Server 2019+ | AIDT 单机内网交付环境 |
| 后端语言 | C# / .NET 10 LTS | 所有业务后端、Worker 和 Adapter |
| 后端框架 | ASP.NET Core | REST API、鉴权、后台服务和健康检查 |
| 应用结构 | 模块化单体 | 单一应用内按身份、对象、流程、审计、连接器等模块隔离 |
| 数据库 | SQL Server 2025 | 关系数据、流程持久化、审计、Outbox 和向量数据统一存储 |
| 前端框架 | Vue 3 | 管理配置端、专业工作台和一线移动端 |
| 前端语言 | TypeScript | 全前端类型化开发 |
| 构建工具 | Vite | 前端构建，仅开发与构建期使用 Node |
| 前端组件 | Element Plus | 统一表单、表格、弹窗、树和后台交互 |
| 状态管理 | Pinia | 全局状态和用户会话状态 |
| 路由 | Vue Router | 权限路由和工作台导航 |
| 工作流 | Elsa Workflows 3.x | 长流程、人工任务、版本、定时和流程持久化 |
| 后台任务 | Hangfire | 对账、补偿、邮件、导入、通知和系统定时任务 |
| 缓存 | Garnet | 会话、缓存、限流和短期分布式锁 |
| 缓存客户端 | StackExchange.Redis | 通过 Redis 协议访问 Garnet |
| 反向代理 | Nginx Stable | TLS、静态资源和 API 代理 |
| AI 网关 | AIDT AiGateway | OpenAI 兼容接口、模型白名单、限流、审计和路由 |
| AI 侧车 | Python 3.12 | 仅用于模型推理、OCR 和文档解析，可选 |
| 主业务 ORM | EF Core | 实体、迁移和常规业务查询 |
| 复杂查询 | Dapper | 报表、对账和性能关键查询 |
| 日志 | Serilog | 结构化日志和 TraceId |
| 文件存储 | 本地目录 + NAS 备份 | 数据库只保存相对路径 |
| 源代码管理 | Git + Gitea | 内网仓库、PR、版本标签和发布记录 |
| 部署方式 | `publish.zip + deploy.ps1 + Windows 服务` | 版本目录、健康检查和自动回滚 |
| 离线交付 | NuGet/npm/pip/模型/安装介质离线包 | 断网可恢复、构建、发布和部署 |

### 4.2 明确不进入 AIDT 的技术

以下技术不作为 AIDT 生产栈：

- Java、Spring Boot、Flowable
- PostgreSQL、MySQL、MongoDB、SQLite（生产环境）
- React、Angular、Next.js、Nuxt
- Blazor 作为业务前端
- Elasticsearch、RabbitMQ、Kafka、GraphQL
- Redis for Windows 3.x 移植版
- S3/MinIO 作为第一期强制依赖
- Docker Desktop、Kubernetes
- 第一阶段拆分为多个独立微服务

### 4.3 Elsa Workflows 的使用边界

- 冻结的是 Elsa Workflows 作为 AIDT 工作流引擎方向，不是直接使用整套 Elsa Studio。
- 业务前端仍统一使用 Vue 3。
- Elsa 只嵌入或部署为 .NET 工作流运行时和 API。
- 不将 Elsa Studio/Blazor 作为面向业务用户的管理端。
- 流程业务人员界面使用 Vue，通过 AIDT 的简化流程配置页面调用标准工作流能力。
- Elsa 的具体 NuGet 版本必须在 PoC 通过后写入 `Directory.Packages.props` 并集中锁定。
- PoC 必须验证会签、或签、退回、委托、SLA、版本冻结、SQL Server 持久化和回滚。

### 4.4 版本锁定规则

冻结的是技术产品和大版本方向，不是允许项目随意升级：

1. `.NET SDK` 版本写入 `global.json`。
2. 所有 NuGet 依赖版本写入 `Directory.Packages.props`。
3. 前端依赖版本通过 `package-lock.json` 锁定，并使用 `npm ci`。
4. Python 依赖通过带哈希的 `requirements.txt` 锁定。
5. 禁止在项目文件中单独写包版本。
6. 禁止使用 `latest`、`*` 或未评审包。
7. 升级统一走季度版本评审、回归测试和 ADR。

### 4.5 不属于本次冻结的内容

以下内容仍需后续确定：

- Elsa 的最终补丁包版本和 `Elsa Studio` 是否仅作为内部管理工具。
- 本地模型名称、量化和 GPU 配置。
- 甲方是否具备 SQL Server 2025 授权。
- U9、ERP、DCS、WMS、LIMS 的具体接口协议。
- 甲方网络、证书、NAS 和多组织部署参数。

## 🧩 五、后端模块边界

建议至少包含：

1. `identity`：组织、用户、角色、权限、数据范围。
2. `metadata`：对象类型、字段、关系、状态机和视图。
3. `business-object`：主对象、版本、关系和变更历史。
4. `workflow`：流程定义、版本、实例、任务和动作。
5. `audit`：审计事件、证据、下载和留存策略。
6. `event`：领域事件、Outbox、订阅和重放。
7. `notification`：站内、钉钉、邮件和升级。
8. `connector`：认证、映射、命令、回执、重试和对账。
9. `document`：附件、文档版本、预览、OCR 和签名。
10. `agent`：数字员工、Skill、运行、确认、预算和熔断。
11. `reporting`：指标口径、聚合和经营驾驶舱。
12. `configuration`：配置草稿、测试、发布、回滚和影响分析。
13. `pmo`：项目主对象扩展、成员、里程碑、事件收件箱和项目任务。

模块之间通过明确应用服务和领域事件交互，不允许跨模块随意读写表。

### 6.1 关键规则

1. 流程实例必须固定启动时的 `workflow_version_id`。
2. 稳定业务字段结构化，动态扩展字段使用 SQL Server JSON 类型能力，不把所有业务数据堆入单一 JSON 列。
3. 业务对象修改保存字段级旧值、新值和版本。
4. 审计表只追加，普通业务接口不得更新或删除。
5. 外部命令保存 `command_id + idempotency_key + approval_evidence + receipt`。
6. 外部事件通过 Outbox 投递，失败进入死信和人工补偿。
7. 对象关系必须有引用完整性和访问权限。

## 🔄 七、流程引擎要求

正式流程引擎冻结为 Elsa Workflows，并且必须覆盖：

- 串行审批
- 会签和或签
- 加签、转办和委托
- 退回、撤回和终止
- 定时器、SLA 和逾期升级
- 条件和决策表
- 子流程
- 版本冻结
- 失败重试、补偿和人工接管
- 运行回放和审计

流程设计器面向业务人员时应隐藏工作流技术复杂度，以“触发、条件、责任人、动作、异常和发布”表达。业务界面使用 Vue 3，不将 Elsa Studio 直接作为 AIDT 业务前端。

统一职责边界：

- Elsa 负责流程实例、人工任务、定时器、版本和流程状态。
- Hangfire 负责系统级后台任务、连接器重试、对账和补偿。
- ASP.NET Core 模块负责业务对象、权限、审计和流程命令。
- SQL Server 保存流程、Outbox、审计和对账状态。
- Vue 3 负责流程配置、待办、详情和工作台交互。

## 🔐 八、身份与权限

权限至少分四层：

1. 组织/部门范围。
2. 项目、客户、批次等业务范围。
3. 字段敏感等级。
4. 动作权限，例如读取、生成草稿、提交、审批、写回和付款申请。

数字员工要求：

- 独立服务身份
- 短期授权令牌
- 明确工具和数据范围
- 独立预算与限额
- 人工确认绑定真实用户身份
- 运行和确认记录绑定流程版本
- 支持停用、熔断和权限复审

## 🔌 九、连接器设计

连接器不是简单 HTTP 封装，而是一个受治理产品能力。

必须具备：

- 认证与密钥轮换
- Schema 和主数据映射
- 幂等控制
- 超时、重试、熔断、死信和人工补偿
- 事件去重与重放保护
- 调用量、延迟、失败率和积压监控
- 业务回执和对账
- 契约测试和版本管理
- 生产写入的审批凭证

推荐流程：

```text
业务命令 → 本地事务 → Outbox → 连接器 → 外部系统
                                │
                                ├─ 成功回执
                                ├─ 重试
                                ├─ 死信
                                └─ 对账/人工补偿
```

## 🚨 十、生产阻断项

以下任一项未完成，不应承载真实业务：

1. 正式认证、SSO、会话和 API 权限校验。
2. 组织、项目、字段和动作级数据范围。
3. 流程版本冻结与实例语义隔离。
4. 不可静默篡改的审计记录。
5. SQL Server 2025 生产数据库、版本化迁移和恢复验证。
6. 备份、恢复演练、监控和告警。
7. 连接器幂等、重试、死信、对账和补偿。
8. 敏感数据分级、加密、密钥管理和模型路由。
9. 生产部署、回滚和应急接管。

## 🧪 十一、进入开发前的 PoC

技术方向已经冻结，但以下 PoC 决定具体包版本和实现边界：

1. **Elsa PoC**：验证会签、或签、退回、委托、SLA、版本冻结、SQL Server 持久化和回滚。
2. **权限 PoC**：验证 ASP.NET Core RBAC 与 AIDT 数据范围、字段敏感等级的组合授权。
3. **连接器 PoC**：验证一个只读接口的认证、映射、分页、重试、Outbox 和对账。
4. **审计 PoC**：验证对象、任务、审批和 Agent 运行能否组成完整证据链。
5. **离线 PoC**：在断网环境完成 `dotnet restore + npm ci + build + publish + deploy.ps1`。

PoC 不写生产系统、不使用真实敏感业务数据。PoC 通过后，将具体依赖版本写入集中版本文件并发布 AIDT Stack 1.0 发布标签。

## 🔒 十二、保密与安全

- 配方、客户、成本、报价、工艺参数和合同属于重点敏感信息。
- 敏感字段需要独立授权、加密和模型路由规则。
- 真实数据不得进入公共模型、公开仓库或未授权演示环境。
- 接口密钥必须使用密钥管理系统，不得写入源码或数据库明文。
