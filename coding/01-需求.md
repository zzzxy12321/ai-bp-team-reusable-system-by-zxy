> 版本：V1.1  
> 冻结状态：**已冻结（FROZEN）**  
> 冻结日期：2026-10-30  
> 定位：产品需求与边界基线  
> 来源：AIDT 全量架构 HTML、现有业务契约、LOCAL-MVP 实现及目标模式资料
> 变更规则：任何范围、业务对象、流程、权限或验收口径变更必须记录 ADR 或变更单，不能由开发窗口自行扩展

## 🎯 一、产品定义

AIDT 是普赛达的企业业务操作系统。它让研发、实验室、生产、质量、设备、EHS、供应链、仓储、交付、客户、财务、人力、法务、项目和经营管理在同一套业务对象、权限、流程、证据和数字员工治理框架上协同，同时保留 U9、ERP、DCS 等专业系统各自的数据权威。

产品的核心价值不是页面数量或流程图数量，而是：

1. 标准能力能否被多个部门复用。
2. 一个现实实体是否只有一个主对象。
3. 跨部门流程能否稳定闭环。
4. 关键动作是否可审计、可追溯、可回放。
5. 数字员工是否在明确授权和人工确认边界内参与执行。

工程交付目标：

> **代码必须适合直接作为甲方便于复制、部署、接手和长期维护的正式代码仓库结构。**

该目标优先于演示速度、页面数量和局部开发便利。Demo 必须作为正式仓库的可运行纵向切片存在，不能采用无法延续到正式交付的临时工程结构。

## 🧠 三、不可破坏的架构原则

### 3.1 对象先行

- 客户、供应商、物料、实验、批次、偏差、合同等现实实体只能有一个主对象。
- 流程实例通过 `object_id` 引用业务对象，不复制对象字段。
- 一个业务对象可以关联多个流程实例。
- 流程实例、任务和证据必须能够反查主对象。

### 3.2 流程负责编排

流程只回答四个问题：

1. 什么时候触发。
2. 满足什么条件。
3. 由谁完成什么动作。
4. 失败、超时或退回后怎么办。

流程不是唯一数据模型，也不能替代业务对象、状态机和主数据。

### 3.3 事件驱动

业务对象创建、状态变化、定时器、外部报警和人工动作可以触发：

- 规则判断
- 流程实例
- 待办任务
- 通知
- 连接器调用
- 数字员工运行
- 审计和证据记录

### 3.4 能力复用

审批、任务、通知、附件、异常、变更、检查表、报表、连接器和审计等横向能力只建设一次。

配置结构目标：

- 80% 通过标准能力包和模板配置完成。
- 15% 通过参数、规则和页面布局调整完成。
- 5% 由平台团队受控扩展。

## 🔐 四、数据权威边界

| 系统 | 权威范围 | AIDT 责任 |
|---|---|---|
| U9 | 财务凭证、总账、应收应付、成本和部分库存账 | 读取、分析、预算前置控制；写入走受控命令接口 |
| ERP | 客户订单、计划、工单、采购交易和库存业务 | 跨部门协同、异常、变更、交付；通过 API/事件交互 |
| DCS/PLC | 实时参数、设备状态、联锁和报警 | 只读报警摘要、批次关联、异常处置和证据；禁止接管安全控制 |
| AIDT | 项目、任务、审批、研发、实验、质量异常、变更、文档、知识和 AI 执行记录 | 业务主账本、流程账本、证据账本和统一入口 |
| 钉钉/HR | 组织身份、消息和移动入口 | SSO、待办、通知和移动审批；不保存业务权威状态 |

硬规则：

- 不直接写 U9、ERP、DCS 业务数据库。
- 跨系统写入必须具备幂等、审批证据、接口回执和补偿。
- DCS 高频参数进入时序存储，不进入普通业务表。
- 外部系统故障时必须能够暂停、补偿、对账或人工接管。

## 🔁 六、四个样板业务流程

### 6.1 客户样品到研发转产

客户需求 → 立项评审 → 配方与实验 → 测试判定 → 试产评审 → 转产发布。

关键证据：

- 客户原始需求和技术确认版本
- 配方版本、实验记录和原始数据
- 样品去向和客户反馈
- 试产、质量评价和转产审批

### 6.2 DCS 越限到批次异常、处置和 CAPA

DCS 报警 → 关联工单与批次 → 班组现场确认 → 工艺质量联合评审 → 偏差/CAPA → 受控回写 ERP/U9。

安全边界：

- AIDT 不得替代 DCS/PLC 联锁。
- 数字员工不得修改控制参数或替代现场安全确认。
- AIDT 只汇总报警、关联批次、生成建议并保存证据。

### 6.3 请购到采购、到货检验和付款

请购 → 预算与采购策略 → 合同/订单 → 到货检验 → 三单匹配 → 付款审批 → 供应商评价。

关键规则：

- 订单、验收和发票必须匹配。
- 付款只能由授权财务人员审批。
- 高金额采购进入重大审批条件节点。

### 6.4 客诉到批次追溯、处置、改进和回访

客诉受理 → 批次与同批去向追溯 → 研发质量联合调查 → 客户处置方案 → CAPA 与体系更新 → 回访关闭。

## 🤖 七、数字员工要求

每个数字员工必须有：

- 独立身份，不得共用真人账号。
- 所属部门、业务负责人和技术负责人。
- 数据范围、工具范围和模型范围。
- A0—A4 执行等级。
- 金额、数量、风险和场景限额。
- 人工确认点或明确免确认条件。
- 输入、工具、模型、输出、成本、审批和回执记录。
- 熔断条件、紧急停止开关和退役机制。

| 等级 | 行为 | 人工边界 |
|---|---|---|
| A0 | 只生成建议 | 所有决定由人做出 |
| A1 | 生成草稿 | 发送或提交前人工确认 |
| A2 | 执行后通知 | 仅限可逆动作 |
| A3 | 限额执行 | 超限、异常或高风险转人工 |
| A4 | 低风险自动闭环 | 必须可监控、可补偿、可停止 |

永久保留人工签认：

- 财务付款
- 质量放行
- 配方变更
- 安全联锁
- 高风险 EHS 作业
- 外部合同承诺
- 客户重大赔付

## 🚦 八、范围优先级

### 8.1 P0：平台内核和最小闭环

- 元数据业务对象与状态
- 动态表单
- 流程模板、流程实例和当前节点
- 待办、通过、退回和终止
- 条件分支
- 事件和审计
- Mock 连接器目录
- 数字员工身份、权限、等级和运行记录
- PC 与移动端基础可用
- API 与浏览器自动化测试
- 至少三条业务链从发起走到完成

### 8.2 P1：运营能力

- 流程实例详情、步骤时间线和证据链
- 对象详情、关系和关联流程
- SLA、逾期升级、任务委托、代理和加签
- 通知与消息模板
- 指标口径和经营驾驶舱
- 连接器契约测试、重试、死信、对账和补偿
- Skill 版本、评测、成本和采用率
- 配置沙箱、影响分析、发布和回滚

### 8.3 P2：规模化

- 多部门模板继承
- 多工厂、多组织和多租户隔离
- 正式 SSO、电子签名和文件管理
- U9、ERP、DCS、WMS、LIMS、仪器和钉钉正式适配
- 数据湖仓、时序库和搜索引擎
- 预测、推荐和复杂智能体编排
- 高可用、灾备、容量规划和多环境发布

## 🔌 九、集成要求

每个连接器至少支持：

- 认证、授权、密钥和证书轮换
- 字段、编码、单位、日期、枚举和主数据映射
- 幂等控制
- 超时、重试、熔断、死信和人工补偿
- 调用量、延迟、失败率、积压和业务异常监控
- 逐日或按批次对账
- 版本管理和契约测试

三类接口：

1. 查询接口：分页、增量、权限和来源标识。
2. 命令接口：幂等、审批凭证和业务回执。
3. 事件接口：状态变化主动推送、去重和重放保护。

## 🔐 十、非功能要求

### 10.1 安全

- 正式身份认证、SSO、会话管理和多因素认证
- RBAC + ABAC，覆盖组织、项目、字段、动作和数据级权限
- 最小权限和敏感字段隔离
- 拒绝访问和越权尝试也写安全审计
- 附件病毒扫描、访问控制和数据留存
- 核心商密不得进入公共模型或公共演示环境

### 10.2 审计与证据

- 记录操作者、时间、对象、旧值/新值、原因、来源和证据引用
- 关键审计不可静默修改或删除
- 对象、流程、任务和数字员工运行可互相追溯
- 外部写入保存审批凭证、幂等键、接口回执和补偿结果

### 10.3 可用性与运维

- 定义 SLA、RTO、RPO、备份频率和恢复演练
- 监控、告警、日志、链路追踪和容量规划
- 数据库迁移、发布、回滚和应急切换
- 单节点故障不得造成任务丢失或重复执行

### 10.4 性能与数据规模

- 列表和审计查询必须分页、筛选并使用索引
- 高频 DCS 数据使用时序存储
- 大批量导入提供预校验、失败行回执和回滚

## ✅ 十一、验收标准

### 业务验收

- 至少三条业务链从发起走到完成
- 至少一个退回和一个终止场景有自动化证据
- 至少一个条件节点能按对象数据进入或跳过
- 任务动作推进实例、生成下一任务并写审计
- 对象、流程、任务、审计和数字员工运行可互相追溯

### 技术验收

- API 契约、数据库迁移和权限测试可重复执行
- 桌面和移动端关键路径均有浏览器验证
- 重复提交、并发推进和连接器重试不产生重复结果
- Mock、已连接、未连接和故障状态明确区分
- 备份恢复、审计不可篡改和越权拒绝经过验证

### 产品验收

- 标准能力复用率目标不低于 80%
- 部门定制后端数量接近 0
- 流程周期、人工触点和重复录入次数持续下降
- 试点部门周活跃率和线上完成率达到约定目标

## 🚫 十二、明确禁止

- 把 AIDT 做成只能画流程、不能管理对象和数据的工具
- 为每个部门独立建设后端
- 用页面数量代替业务闭环和能力复用
- 让数字员工控制 DCS/PLC、直接付款、质量放行或修改批准配方
- 把 mock 描述为真实系统或真实 AI 结论
- 未经授权连接真实系统、发送消息或产生付款
- 把本地 SQLite 演示库直接当作生产数据库

## ❓ 十三、待决策事项

1. 本地机房、私有云、公有云或混合云部署。
2. 钉钉、AD/LDAP 或其他企业身份源。
3. 等保、数据分级、审计留存和电子签名要求。
4. U9、ERP、DCS、WMS、LIMS 的真实接口和网络条件。
5. 第一批试点部门和三条样板流程。
6. 研发、实施、测试、运维和安全团队规模。
7. 是否采购 BPM、文档、电子签或低代码产品。
8. 生产 SLA、RTO、RPO 和最大用户/数据量。
9. 多法人、多工厂、多组织是否第一期上线。
10. 预算和业务优先级对应的正式实施周期。
