# 构建、部署、回滚与离线交付规范

## 🎯 部署基线

- Windows Server 2019+
- .NET 10 应用以 Windows 服务运行
- Nginx 作为唯一外部入口
- SQL Server 2025 只监听本机或受控网络
- Garnet 只监听本机
- 前端构建后为静态文件，生产服务器不运行 Node
- 不使用 Docker Desktop 或 Kubernetes

## 📦 发布产物

每次发布必须生成：

```text
AIDT-{version}/
├─ backend/
├─ frontend/dist/
├─ database/
├─ deploy/
├─ offline-packages/
├─ manifest.json
├─ checksums.sha256
└─ release-notes.md
```

`manifest.json` 至少包含：

- 应用名称和版本
- Git 提交号
- 构建时间
- .NET SDK 版本
- Node 构建版本
- 依赖锁定文件哈希
- 数据库迁移版本
- 发布人
- 产物 SHA256

## 🧱 版本目录

```text
D:\Apps\AIDT\{version}\
D:\Apps\AIDT\current
D:\Data\AIDT\uploads
D:\Logs\AIDT
D:\Secrets
D:\Backup
```

部署流程：

1. 停止对应 Windows 服务。
2. 记录当前版本和回滚点。
3. 备份数据库。
4. 解压新版本到独立目录。
5. 执行数据库迁移。
6. 切换 `current` 目录联接。
7. 启动服务。
8. 检查 `/health/live` 和 `/health/ready`。
9. 执行关键烟雾测试。
10. 失败则恢复到上一版本和数据库备份。

## 🗃️ 数据库发布

- 生产环境禁止应用启动时自动迁移。
- 迁移前必须全量备份。
- 高风险脚本先在生产同规模测试库验证。
- 迁移有锁表和执行时间评估。
- 失败立即停止，不继续切换到新应用。
- 破坏性数据变更使用扩展—迁移—收缩。

## 🌐 Nginx

- 只做 TLS、静态资源和反向代理。
- 不允许直接暴露 SQL Server、Garnet 或内部应用端口。
- AI 流式接口关闭代理缓冲。
- 上传大小与超时按业务配置。
- 访问日志不得记录敏感查询参数。
- 配置纳入版本管理。

## 🔄 回滚

回滚必须考虑：

- 应用版本
- 数据库结构
- 数据库数据
- 配置文件
- 前端静态资源
- 外部系统已写回命令

规则：

- 应用回滚和数据库回滚必须分别验证。
- 已产生外部副作用的命令不能简单回滚，需要补偿。
- 回滚演练必须在测试环境完成。
- 回滚结果写入部署记录。

## 📴 离线交付

仓库或发布包必须包含：

- NuGet 离线包
- npm 缓存或已锁定依赖
- Python wheelhouse（启用 AI 侧车时）
- .NET Hosting Bundle
- SQL Server、Nginx、Garnet 安装介质说明
- 模型文件和 SHA256（启用模型时）
- CA 证书和安装说明

断网验证：

```powershell
dotnet restore --source .\offline\nuget
dotnet build --no-restore
dotnet publish --no-restore
npm ci --offline
npm run build
.\deploy\deploy.ps1
```

任何依赖必须能够从离线产物恢复，不能依赖开发者本机缓存。

## 🚨 发布门禁

- 版本已冻结
- 测试通过
- 备份恢复演练完成
- 数据库迁移审核
- 配置差异已核对
- 密钥已注入
- 性能无明显回退
- 回滚包可用
- 业务验收人确认
- 发布窗口和责任人明确

## 🧾 部署记录

每次部署记录：

- 应用版本
- Git 提交
- 执行人
- 开始和结束时间
- 数据库迁移版本
- 健康检查结果
- 烟雾测试结果
- 回滚点
- 异常和处置

## 🚫 部署反模式

- 直接覆盖旧目录
- 无备份迁移
- 生产环境手工拷贝 DLL
- 在服务器执行 `npm install`
- 使用未锁定依赖
- 失败后继续启动
- 只检查进程是否启动
- 不保存发布包和校验和
- 不演练回滚
