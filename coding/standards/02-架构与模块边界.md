# 架构与模块边界规范

## 🎯 架构基线

AIDT 采用 Windows 单机内网部署、ASP.NET Core 模块化单体、Vue 3 前端、SQL Server 2025 和 Elsa Workflows。第一阶段不允许拆成微服务，不允许引入第二数据库或第二业务后端。

## 🧱 后端分层

```text
AIDT.Api
  ↓
AIDT.Application
  ↓
AIDT.Domain
  ↑
AIDT.Infrastructure
```

### AIDT.Api

负责：

- HTTP 路由和版本
- 身份解析
- 请求 DTO 绑定
- 权限过滤器
- 统一响应和全局异常
- OpenAPI

禁止：

- 直接访问 DbContext
- 编写业务规则
- 直接调用外部系统
- 在 Controller 内开启长事务

### AIDT.Application

负责：

- 用例编排
- 事务边界
- 权限和业务规则调用
- DTO 转换
- 幂等和并发控制
- Outbox 写入

禁止：

- 包含 SQL Server 专属实现
- 直接依赖 HTTP、Cookie 或 Vue
- 绕过领域规则直接改状态

### AIDT.Domain

负责：

- 业务实体
- 状态转换
- 值对象
- 领域规则
- 领域事件

禁止：

- 依赖 EF Core、Dapper、ASP.NET Core
- 调用外部接口
- 读取配置或日志基础设施

### AIDT.Infrastructure

负责：

- EF Core
- Dapper
- SQL Server
- Garnet
- 外部 Adapter
- 文件存储
- 日志和外部服务实现

## 🧩 功能模块

建议模块：

1. Identity：身份、组织、角色、权限、数据范围
2. Metadata：对象类型、字段、关系、状态机、视图
3. BusinessObject：主对象、版本和状态
4. Workflow：Elsa 集成、任务、动作、版本和回放
5. Audit：审计、证据和导出
6. Event：领域事件、Outbox 和订阅
7. Notification：站内、钉钉、邮件和升级
8. Integration：连接器、命令、回执、重试和对账
9. Document：附件、版本、OCR、签名
10. Agent：数字员工、Skill、运行和确认
11. Reporting：指标、聚合和驾驶舱
12. Configuration：配置版本、测试、发布和回滚

## 🔗 依赖规则

1. 模块只能通过 Application 接口或领域事件交互。
2. 禁止一个模块直接查询另一个模块的私有表。
3. 禁止共享可变实体。
4. 共享代码只允许稳定的基础类型、结果类型和抽象契约。
5. 跨模块报表通过只读查询接口、专用视图或 Reporting 模块实现。
6. 模块之间不能形成循环依赖。
7. 公共契约变化必须检查所有调用方和功能地图。

## 🗄️ 数据所有权

每个模块拥有独立 SQL Server Schema，例如：

- `Identity`
- `Metadata`
- `BusinessObject`
- `Workflow`
- `Audit`
- `Integration`
- `Agent`

规则：

- 一个表只能有一个所有者模块。
- 其他模块不得直接写表。
- 跨模块读取必须通过明确契约。
- 审计表只追加。
- 工作流实例必须绑定流程版本。
- 外部命令必须有 Outbox 和回执。

## 🌐 前端分层

```text
pages/          页面壳和路由入口
features/       业务功能组件、API 和状态
components/     可复用无业务组件
layouts/        页面布局
stores/         跨页面状态
api/            统一 HTTP 客户端和契约类型
router/         路由和权限守卫
```

规则：

- 业务逻辑放在 feature 内的 composable、store 或应用服务，不放在模板。
- 页面不得直接拼接随意 URL，必须使用 API client。
- 跨功能状态必须有明确所有权。
- 可复用组件不得依赖具体业务流程。

## 🔄 工作流边界

- Elsa 负责流程实例、人工任务、定时器、版本和流程状态。
- AIDT Application 负责发起、处理、退回、终止和业务对象联动。
- Hangfire 只负责系统后台任务和连接器补偿。
- SQL Server 是流程、Outbox、审计和对账的持久化存储。
- Vue 负责人工操作和简化流程配置，不直接操作 Elsa 表。

## 📐 ADR 触发条件

出现以下任一情况必须写 ADR：

- 更换技术栈或核心库
- 新增数据库、消息队列、缓存或搜索引擎
- 改变模块边界或数据所有权
- 引入跨模块同步事务
- 改变身份、权限、审计或数据分级模型
- 增加新的部署组件
- 影响两个以上团队或甲方交付方式
- 需要临时违反任一规范

## 🚫 架构反模式

- Controller 直接写 SQL。
- Application 直接返回 EF 实体。
- 一个模块直接修改另一个模块的表。
- 前端页面直接调用多个未统一接口并自行拼装业务状态。
- 用共享数据库视图绕过模块契约。
- 工作流复制业务对象字段。
- 审计表允许普通接口更新或删除。
- 每个甲方创建独立代码分支。
