# 安全、权限、审计、配置与事务规范

## 🎯 安全目标

AIDT 处理研发、质量、供应链和经营管理数据。安全规则是系统边界，不是可选增强项。

## 👤 身份认证

- 真人用户使用企业身份源或 ASP.NET Core Identity。
- 浏览器端优先使用 HttpOnly、Secure、SameSite Cookie。
- 服务账号和数字员工使用独立身份与短期令牌。
- 禁止共享账号。
- 关键账户支持多因素认证。
- Cookie 鉴权必须有 CSRF 防护。
- 登录、失败、锁定和退出必须审计。

## 🛂 权限模型

采用 RBAC + ABAC：

1. RBAC：角色允许访问哪些菜单、接口和动作。
2. 组织范围：部门、工厂、班组。
3. 业务范围：项目、客户、批次、流程实例。
4. 字段范围：公开、内部、敏感、核心。
5. 动作范围：读取、草稿、提交、审批、写回、付款申请。

必须同时执行：

- 菜单可见性
- API 接口权限
- 数据范围过滤
- 字段脱敏
- 高风险动作确认

任何一层缺失都视为权限缺陷。

## 🔐 数据分级

| 级别 | 示例 | 规则 |
|---|---|---|
| L1 公开 | 公开资料 | 可按授权公开 |
| L2 内部 | 制度、会议 | 仅内网授权用户 |
| L3 敏感 | 客户、报价、工艺 | 最小权限、脱敏、审计 |
| L4 核心 | 配方、源代码、财务 | 严格隔离，禁止公共模型 |

要求：

- 字段级敏感等级登记在元模型。
- L3/L4 导出、修改和批量查询必须审计。
- L4 数据不得进入外部模型。
- 数字员工数据范围不得大于其业务负责人。

## 🧾 审计

必须审计：

- 登录、退出、失败和锁定
- 对象创建、修改、状态变化和删除
- 流程发起、通过、退回、终止、转办和委托
- 权限变更和数据范围变更
- 导出、批量导入和附件下载
- 外部命令、回执、重试和补偿
- 数字员工运行、人工确认和停止

审计至少包含：

- 谁
- 何时
- 什么对象
- 什么动作
- 旧值/新值或差异
- 原因
- TraceId
- 来源 IP/终端（合规允许时）
- 流程或命令关联 ID

审计表只追加。普通业务账号无更新和删除权限。审计失败时，高风险业务动作应失败而不是静默继续。

## 🔑 配置与密钥

- 配置使用 `appsettings` + 环境变量覆盖。
- 密钥不进入 Git、日志、前端或提示词。
- 生产密钥存放 `D:\Secrets` 或受管密钥服务。
- 文件 ACL 只授予服务账号。
- 连接串按最小权限配置。
- 模型 API Key 仅在 AiGateway 中保存。
- 配置启动时强校验。
- 环境配置不允许通过 URL 或调试接口暴露。

## 🛡️ 应用安全

- 参数化 SQL，禁止拼接。
- 用户输入做类型、长度、枚举和业务校验。
- 文件上传校验扩展名、MIME、大小和病毒扫描状态。
- 文件名使用 GUID，不使用原始路径。
- 前端默认文本转义，禁止不可信 `v-html`。
- 配置 CSP、X-Frame-Options、HSTS 等安全响应头。
- 最小 CORS 白名单。
- 登录和敏感接口有限流。
- 内部服务只监听 `127.0.0.1`。

## 📝 日志规范

结构化字段：

- TraceId
- UserId
- AppId
- Module
- Action
- EntityType
- EntityId
- Outcome
- DurationMs

规则：

- 默认 Information。
- 不打印密码、令牌、连接串和完整敏感数据。
- AI 日志不记录完整 Prompt 和完整业务原文。
- 外部接口记录摘要、状态码、耗时和 TraceId。
- 日志保留期和访问权限明确。

## 🔄 事务规范

1. 一个应用用例定义一个事务边界。
2. Controller 不开启事务。
3. Repository 不开启独立嵌套事务。
4. 事务内禁止 HTTP、模型和长耗时调用。
5. 业务记录与 Outbox 在同一事务写入。
6. 外部调用由 Worker 执行并记录回执。
7. 失败可重试且幂等。
8. 跨系统写入无法原子时必须有补偿和对账。

## 🔁 外部写回

流程：

1. 校验授权和审批证据。
2. 在本地事务创建命令和 Outbox。
3. Worker 调用 Adapter。
4. 保存回执或错误。
5. 失败重试并进入死信。
6. 对账任务检查源系统和 AIDT 差异。
7. 人工补偿必须写审计。

## 🤖 AI 与数字员工

- 独立身份和最小权限。
- 数据范围、工具范围、模型白名单。
- 输出不能直接写生产库。
- 工具调用有白名单和沙盒。
- 高风险动作人工确认。
- 运行预算、超时、熔断和停止开关。
- 运行记录可追溯 Skill、模型、输入摘要和确认人。

## 🚫 安全反模式

- 只隐藏菜单不校验 API
- 前端传入 userId 作为可信身份
- 使用 `sa`
- 密钥写入配置文件
- 全量日志打印业务原文
- Cookie 鉴权无 CSRF 防护
- 数字员工共用真人账号
- 外部系统直连数据库
- 重试无幂等
- 审计可修改或删除
