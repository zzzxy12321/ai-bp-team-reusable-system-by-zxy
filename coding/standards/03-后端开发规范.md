# 后端开发规范

## 🎯 适用范围

适用于 `backend/` 下所有 ASP.NET Core、Application、Domain、Infrastructure、Workflow、Integrations 和 Worker 项目。

## 🏷️ 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 命名空间 | PascalCase，按项目/模块 | `AIDT.Workflow.Application` |
| 类、接口、枚举 | PascalCase | `WorkflowInstanceService` |
| 接口 | `I` 前缀 | `IWorkflowRepository` |
| 方法 | PascalCase，动词优先 | `SubmitWorkflowAsync` |
| 局部变量和参数 | camelCase | `workflowInstanceId` |
| 私有字段 | `_camelCase` | `_dbContext` |
| 常量 | PascalCase | `DefaultPageSize` |
| 异步方法 | `Async` 后缀 | `GetInstanceAsync` |
| DTO | 明确用途后缀 | `CreateWorkflowRequest` |
| 异常 | `Exception` 后缀 | `WorkflowConflictException` |
| 测试 | `Method_Scenario_Expected` | `Approve_WhenTaskProcessed_ReturnsConflict` |

禁止无语义缩写，例如 `svc`、`mgr`、`tmpObj`、`data1`。

## 🧩 Controller 规范

Controller 只负责：

- 接收请求
- 绑定和基础模型验证
- 获取可信用户身份
- 调用 Application 用例
- 返回统一响应

Controller 禁止：

- 直接访问数据库
- 编写业务分支
- 开启事务
- 直接调用外部 API
- 把异常吞掉
- 返回 EF 实体

## ⚙️ Application 规范

每个业务动作对应一个明确用例，例如：

- `CreateWorkflowInstance`
- `ApproveTask`
- `ReturnTask`
- `RejectWorkflow`
- `ConfirmAgentRun`

用例必须：

1. 验证输入。
2. 校验身份、权限和数据范围。
3. 读取并验证当前状态。
4. 在明确事务内修改数据。
5. 写审计和 Outbox。
6. 返回结果 DTO。
7. 不隐藏部分失败。

## ✅ 验证规范

- API 只做格式级验证。
- 业务规则在 Application/Domain 中验证。
- 数据库约束是最后防线。
- 错误返回稳定错误码。
- 不得依赖前端 required 作为安全边界。

## ⚠️ 异常处理

统一异常层级：

- `ValidationException`
- `AuthenticationException`
- `AuthorizationException`
- `NotFoundException`
- `ConflictException`
- `ExternalServiceException`
- `UnexpectedException`

规则：

- 业务异常携带稳定错误码。
- 不把数据库异常原文返回前端。
- 未预期异常记录 TraceId 和完整服务端日志。
- 不允许空 `catch`。
- 不允许用异常控制正常循环。

## 📝 日志规范

结构化日志字段至少包含：

- `TraceId`
- `UserId`
- `Module`
- `Action`
- `EntityType`
- `EntityId`
- `Outcome`
- `DurationMs`

禁止记录：

- 密码、令牌、密钥、连接串
- 完整身份证、手机号和客户敏感信息
- 完整 Prompt 或 L3/L4 业务数据

## 🔄 事务规范

1. 一个用例一个明确事务边界。
2. 跨表业务写入必须原子。
3. 事务内禁止调用 HTTP、模型或耗时外部服务。
4. 外部调用通过 Outbox 和 Worker。
5. 长事务必须拆分为可恢复步骤。
6. 并发更新使用版本号或行版本。
7. 事务失败必须回滚业务状态和 Outbox。

## 🔁 幂等与并发

- 外部写命令必须有 `IdempotencyKey`。
- 任务处理必须原子更新并检查影响行数。
- 同一资源更新必须使用乐观并发。
- 同一失败消息重试不得产生重复业务记录。
- 冲突返回 `409` 或明确业务错误码。

## ⏱️ 异步规范

- I/O 操作必须使用异步 API。
- 传递 `CancellationToken`。
- 禁止 `.Result`、`.Wait()` 和异步阻塞。
- 后台任务必须支持超时、重试和幂等。
- 流式 AI 调用设置独立超时。

## 🧰 配置规范

- 使用 Options 模式。
- 环境配置覆盖默认配置。
- 密钥不进入 `appsettings.json` 或 Git。
- 生产密钥存放在 `D:\Secrets` 或安全注入机制。
- 启动时校验必填配置，缺失立即失败。
- 不在代码中写死端口、连接串、路径和模型地址。

## 🧱 后台任务

Hangfire 任务必须：

- 使用稳定任务 ID
- 幂等
- 有最大重试次数
- 有超时
- 有死信或失败队列
- 记录业务关联 ID
- 必要时支持人工重放

Elsa 定时器和 Hangfire 定时器职责不得重复。

## 💾 缓存规范

- Garnet 不作主存储。
- 缓存键必须包含模块、对象和版本。
- 写入数据库后明确失效策略。
- 不缓存权限以外的敏感明文。
- 缓存失败不得导致核心业务错误。

## 🧪 单元测试要求

- Domain 状态转换必须有单元测试。
- Application 用例必须覆盖成功、校验失败、权限拒绝和并发冲突。
- 外部服务使用明确 Mock。
- 不允许测试真实生产数据。

## 🚫 后端反模式

- Fat Controller
- Repository 内部开启独立事务
- 全局静态可变状态
- 吞异常后返回成功
- 同步阻塞异步代码
- 直接写其他模块的表
- 事务中调用外部系统
- 日志输出敏感数据
