# 前端开发规范

## 🎯 适用范围

适用于 `frontend/` 下所有 Vue 3 + TypeScript + Vite + Element Plus 应用。

## 📁 推荐目录

```text
frontend/src/
├─ api/
│  ├─ http.ts
│  ├─ types/
│  └─ modules/
├─ components/
│  ├─ base/
│  └─ business/
├─ features/
│  ├─ workflow/
│  ├─ business-object/
│  ├─ audit/
│  ├─ agent/
│  └─ integration/
├─ layouts/
├─ pages/
├─ router/
├─ stores/
├─ styles/
├─ utils/
└─ main.ts
```

规则：

- `pages` 只做路由和页面组装。
- `features` 拥有业务组件、composable、store 和 API。
- `components/base` 不包含业务流程。
- `components/business` 包含可复用业务组件，但必须有稳定契约。
- `api/modules` 统一封装后端接口。

## 🏷️ 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| Vue 组件 | PascalCase | `WorkflowInstanceCard.vue` |
| 页面 | PascalCase + Page | `WorkflowListPage.vue` |
| composable | `use` + PascalCase | `useWorkflowActions.ts` |
| Pinia store | `useXxxStore` | `useWorkflowStore.ts` |
| API 文件 | camelCase + Api | `workflowApi.ts` |
| 类型 | PascalCase | `WorkflowInstanceDto` |
| 常量 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` |
| CSS class | kebab-case | `workflow-timeline` |

## 🧠 组件规范

- 组件只负责单一视觉/交互职责。
- 页面不直接包含复杂业务计算。
- 组件 props 必须定义类型和默认值策略。
- emits 必须显式声明。
- 避免超过 300 行的单文件组件，超过时拆分。
- 不在模板中调用复杂函数。
- 不把 API 地址和业务常量硬编码在组件。

## 🔌 API 调用规范

1. 所有 HTTP 调用必须经过 `api/http.ts`。
2. 认证、TraceId、错误提示和超时统一处理。
3. 每个模块建立单独 API client。
4. API 类型必须与 OpenAPI 契约一致。
5. 页面不得自行拼接 URL。
6. API 错误必须转为明确页面状态。
7. 写请求必须支持幂等键或服务端防重复机制。

## 🗃️ 状态管理

- 局部交互状态留在组件。
- 跨页面或跨组件共享状态进入 Pinia。
- 服务端数据不默认全部复制到 store。
- store 必须按业务模块划分。
- 不在 store 中直接操作 DOM。
- 权限和用户身份由独立 store 管理。

## 🛣️ 路由与权限

- 路由使用模块化配置。
- 页面权限由路由守卫和后端接口权限双重校验。
- 隐藏菜单不等于禁止访问。
- 无权限页面必须显示明确状态，不无限加载。
- 路由参数必须验证并处理无效 ID。

## 🧩 错误与加载状态

每个页面至少定义：

- loading
- empty
- success
- validation-error
- permission-denied
- network-error
- server-error

不得出现请求失败后页面空白且无提示。

## 🎨 视觉与交互

- 统一使用 Element Plus 组件和公司设计 token。
- 颜色、间距、圆角、字号使用 CSS 变量。
- 不因单个页面引入第二套组件库。
- 表格、弹窗、表单必须适配桌面和移动端。
- 关键按钮有明确 loading 和 disabled 状态。
- 高风险操作必须二次确认并显示影响。
- 所有弹窗支持键盘关闭和焦点管理。

## ♿ 可访问性

- 表单控件必须有 label。
- 图标按钮必须有 aria-label。
- 颜色不能作为唯一状态表达。
- 键盘可以完成核心操作。
- 错误信息与对应字段关联。

## 🔐 前端安全

- 不把密钥、内部令牌或生产配置打入静态文件。
- 用户输入默认按文本显示，禁止未转义 `v-html`。
- 外部链接使用安全 rel。
- 文件上传校验类型、大小和文件名。
- 不在 URL 中放置敏感信息。
- 不在前端保存长期高权限令牌。

## 🧪 前端测试

- 基础组件：属性、事件、空状态、错误状态。
- 页面：加载、成功、空、失败、无权限。
- 关键流程：浏览器端到端。
- 响应式：至少桌面和 390px 移动端。
- 回归：Bug 修复必须增加对应页面测试。

## 🚫 前端反模式

- 第二套 UI 组件库
- 页面直接 `fetch`
- 复杂业务逻辑写在模板
- 全局 store 承载所有状态
- 隐藏菜单代替权限控制
- 使用 `v-html` 渲染未可信内容
- 无错误状态、无加载状态
- 只为桌面验证就宣称完成
