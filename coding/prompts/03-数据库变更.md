# 目标模式提示词：数据库变更

你要为 AIDT 设计并实施一次数据库变更。

## 输入

- 变更目标：
- 相关 Feature ID：
- 预计表/字段：
- 是否破坏性：

## 开始前

读取：

- `AGENTS.md`
- 项目目标、需求、冻结技术栈
- 架构规范
- 数据库与迁移规范
- API、安全和测试规范
- 功能地图和相关模块 README

## 必须输出设计

1. 数据模型变化
2. 表、字段、类型、约束
3. 关系和数据所有权
4. 索引和查询场景
5. 权限和敏感等级
6. 审计要求
7. JSON 使用必要性
8. 数据量估计
9. 锁表和执行时间风险
10. 迁移步骤
11. 回滚方式

## 实施规则

- 使用 SQL Server 2025。
- EF Core 迁移是源代码变更。
- 生产迁移脚本进入 `database/migrations/`。
- DBA 审核进入 `database/dba-review/`。
- 不在应用启动时自动迁移生产库。
- 破坏性变更使用扩展—迁移—收缩。
- 不使用 `SELECT *` 和字符串拼接 SQL。
- 模块不直接操作其他模块表。

## 测试

- 空库执行全部迁移
- 上一版本库升级
- 约束与索引
- 权限和审计
- 事务回滚
- 备份恢复
- 相关 API 和业务回归

## 输出

1. 数据模型
2. 迁移文件
3. 回滚方案
4. 测试证据
5. 兼容性影响
6. 部署顺序
7. 未完成风险
