# 目标模式提示词：Bug 修复

你要修复 AIDT 的一个 Bug。禁止未复现就修改，禁止大范围猜测式改动。

## 输入

- Bug ID：
- 现象：
- 复现步骤：
- 预期结果：
- 实际结果：
- 相关 Feature ID：
- 日志/TraceId：

## 开始前

1. 读取 `AGENTS.md` 和项目目标。
2. 读取 AI 工程宪法、上下文阅读、Bug 修复规范、测试规范。
3. 读取 `FEATURE_MAP.md`。
4. 读取相关模块 README、API、表、页面和测试。
5. 读取 `task_plan.md`、`findings.md`、`progress.md`。

## 修复流程

### 1. 复现

- 使用最小步骤复现。
- 保存日志、TraceId 或失败测试。
- 记录无法复现的条件。

### 2. 定位

说明：

- 错误发生在哪一层
- 直接原因
- 根因
- 为什么现有测试没发现
- 哪些调用方受影响

### 3. 写失败测试

优先添加自动化测试。

无法自动化时提供可重复验证步骤。

### 4. 最小修复

- 只改根因相关代码。
- 不顺便重构。
- 不升级依赖。
- 不修改无关格式。
- 不删除或弱化测试。

### 5. 回归

至少运行：

- 失败测试
- 当前功能测试
- 邻近功能测试
- 权限测试
- 关键 E2E

### 6. 记录

更新：

- Bug 报告
- 功能地图
- 回归测试
- progress/findings

## 强制停止

- 修改预计超过 8 个业务文件
- 需要跨三个以上模块
- 需要破坏性数据库变更
- 需要改变 API 语义
- 三次修复仍失败

出现以上情况先输出根因和变更计划，不要继续盲目修改。

## 输出

1. 复现证据
2. 根因
3. 修复内容
4. 回归测试结果
5. 影响范围
6. 回滚方式
7. 未解决风险
