# 目标模式提示词：新功能开发

你要为 AIDT 开发一个新功能。

## 输入

- Feature ID：
- 功能名称：
- 业务目标：
- 验收标准：
- 目标模块：
- 是否涉及 API：
- 是否涉及数据库：
- 是否涉及权限/审计：

## 开始前

1. 完整读取 `AGENTS.md`。
2. 读取项目目标、需求、冻结技术栈。
3. 读取 AI 工程宪法、上下文阅读、架构、Vibecoding 工作流。
4. 读取 `FEATURE_MAP.md` 中的相关条目。
5. 读取对应模块 README、API 规范、数据库规范、安全规范和测试规范。
6. 读取 `task_plan.md`、`findings.md`、`progress.md`。

## 第一阶段：上下文和影响分析

输出并写入 `task_plan.md`：

- 功能 ID 和验收标准
- 当前行为
- 预期行为
- 相关页面和路由
- 相关后端模块
- 相关 API
- 相关数据表
- 相关工作流
- 相关权限和审计
- 预期修改文件
- 明确不修改范围
- 回归测试
- 回滚方式

缺少关键信息时优先从项目文档和代码中查证，不自行扩大范围。

## 第二阶段：计划和契约

按顺序完成：

1. API/OpenAPI 契约
2. 数据库迁移
3. 后端用例
4. 前端 API 类型和页面
5. 测试
6. 功能地图

## 第三阶段：实现

- 遵守模块边界。
- 不跨模块写表。
- 不引入未评审依赖。
- 不修改无关文件。
- 完成成功、失败、权限、空状态和并发路径。
- 每个关键步骤写入 `progress.md`。

## 第四阶段：测试

- 单元
- 集成
- API 契约
- 权限
- 前端组件/页面
- 浏览器 E2E
- 数据库迁移
- 邻近功能回归

测试失败先修根因，不修改断言掩盖错误。

## 第五阶段：自审

从三个视角审查：

- 架构：分层、模块、契约、数据所有权
- 行为：边界、并发、权限、错误和空状态
- 交付：测试、文档、迁移、部署和回滚

## 输出

1. 功能结果
2. 修改文件
3. API/数据库变化
4. 测试命令和结果
5. 回归范围
6. 风险和未完成项
7. 功能地图更新

没有验证证据不得宣布完成。
