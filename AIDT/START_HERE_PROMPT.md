## 最终目标

依据 AIDT HTML 蓝图，持续加固并扩展本地纵向样板。今晚必须真实打通并证明：

> 业务对象 → 流程实例 → 自动生成待办 → 人工审批/退回/终止 → 数据条件跳转 → 审计证据 → 数字员工受控辅助。

这不是静态网页任务。不得只写计划、设计文档或假数据页面。你需要在本地实现可操作功能，并运行 API 和浏览器测试。

## 不可破坏的架构原则

1. 对象先行。一个现实实体只有一个主对象，流程引用对象，不复制对象。
2. 流程只负责编排对象上的动作，不是唯一数据模型。
3. U9 是财务权威，ERP 是订单与计划权威，DCS 是实时控制权威。
4. AIDT 负责统一业务数据面、跨部门流程、任务、证据和智能辅助。
5. U9、ERP、DCS、钉钉当前只能使用明确标记的 mock provider，禁止声称已真实打通。
6. 禁止直接写外部系统数据库。
7. 禁止数字员工控制 DCS/PLC、直接付款、直接质量放行或修改批准配方。
8. 数字员工必须有独立身份、数据范围、执行等级、人工确认和运行审计。
9. 所有流程动作必须写审计，跨系统写入必须具备幂等和补偿设计。
10. 部门配置必须基于标准能力包，禁止为每个部门新建独立后端。

## 禁止事项

- 不连接真实 U9、ERP、DCS、钉钉或外部大模型。
- 不发送真实邮件、消息，不产生真实付款或外部业务副作用。
- 不引入真实配方、客户、成本、报价、工艺参数。
- 不将 mock 结果描述成真实系统或真实 AI 结论。
- 不为了增加页面数量跳过测试。
- 不修改 `AIDT` 目录之外的用户文件。
- 不删除用户数据；只能重置本项目自己的演示数据库。

## 执行顺序

### 第一阶段：审计现有基线

1. 检查当前服务、数据库、API 和前端代码。
2. 运行：

```powershell
node --check .\server.mjs
node --check .\public\app.js
node .\tests\api-smoke.mjs
node .\tests\browser-smoke.mjs
```

3. 将失败记录到 `progress.md` 和 `findings.md`。
4. 现有测试未全部通过前，不增加新功能。
5. 每次修改服务端代码后，先运行 `stop.ps1` 停止旧进程，再运行 `start.ps1` 启动新代码；不得让自动化测试误测旧服务。

### 第二阶段：核心加固

按优先级完成：

1. API输入校验和可理解错误返回。
2. 流程实例详情接口和页面，展示对象字段、步骤时间线、处理人、决定、意见和审计。
3. 任务退回测试。
4. 流程终止测试。
5. 重复提交和并发推进的幂等保护。
6. mock/真实/未连接状态始终清晰区分。

### 第三阶段：最多两个增强项

只有前两阶段全部通过后，才从以下方向选择最多两个：

- 对象详情和关联流程实例。
- 流程定义只读可视化。
- SLA逾期升级。
- 数字员工运行与流程实例关联视图。
- 连接器契约检查。
- 任务待办和流程实例双向跳转。

不得扩展成13个部门的完整页面群，不得牺牲核心闭环和测试。

## 定义完成

以下条件全部满足才算完成：

- 至少两条业务链能从发起走到完成。
- 退回和终止至少各有可验证证据。
- 至少一个条件节点能根据业务数据自动进入或跳过。
- 任务动作会推进实例、生成下一任务并写审计。
- mock 与真实连接边界清楚。
- 数字员工有独立身份、等级、权限、人工确认和运行记录。
- API 自动化测试通过。
- 浏览器导航、任务处理、发起流程、数字员工弹窗和移动端测试通过。
- `progress.md` 记录证据，而非只写“已完成”。
