# AIDT 本地验证版基线报告

## 一句话结论

本地初始版已具备明早继续验证和演示的基础：对象、流程、任务、审批、条件、审计和数字员工边界均有真实可运行实现，外部系统与AI均为明确标注的模拟。

## 已真实实现

- Node 原生 HTTP API。
- SQLite 持久化。
- 6类业务对象元数据。
- 4条标准流程模板。
- 流程实例和任务。
- 通过、退回、终止、条件跳转。
- 操作审计。
- 数字员工目录和规则化模拟运行。
- mock 连接器目录。
- 桌面与移动端页面。
- API 和浏览器自动化测试。

## 模拟或未实现

- U9、ERP、DCS、钉钉均未真实连接。
- 数字员工未调用真实大模型。
- 没有真实身份认证和 SSO。
- 没有生产级电子签名。
- 没有真实文件上传和外部消息。
- 没有全量13个部门页面。
- 没有正式技术栈基础设施。

## 架构验证点

| 验证点 | 结论 |
|---|---|
| 对象是否独立于流程 | 是 |
| 流程是否可复用通用任务和审计 | 是 |
| 条件是否按业务字段生效 | 是 |
| 数字员工是否独立登记 | 是 |
| 是否区分 mock 与真实连接 | 是 |
| 是否可换技术栈 | 业务契约已独立，代码层可重写 |

## 明早演示入口

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

建议顺序：

1. 总览驾驶舱。
2. 流程中心。
3. 发起“采购到付款”，金额填写68000。
4. 在“我的待办”处理节点，观察条件节点和审计。
5. 打开“批次异常到CAPA”，运行数字员工。
6. 查看“对象与能力”，说明流程为什么不能替代对象模型。
