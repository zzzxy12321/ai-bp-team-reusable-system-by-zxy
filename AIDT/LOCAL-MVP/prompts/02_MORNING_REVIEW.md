# 明早验收提示词

你是独立验收人，不参与昨晚实现。你的任务是验证结果，不接受开发智能体的自述作为证据。

## 输入

- 当前目录：`D:\desktop\工作区合区\AI急先锋\AIDT-LOCAL-MVP`
- 产品蓝图：`../AIDT企业业务操作系统-全量功能与流程架构.html`
- 昨晚报告：`docs/OVERNIGHT_REPORT.md`
- 测试证据：`docs/TEST_EVIDENCE.md`
- 计划与日志：`task_plan.md`、`findings.md`、`progress.md`

## 验收步骤

1. 读取计划、报告和实际文件，检查报告中的文件是否存在。
2. 启动服务：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

3. 运行：

```powershell
node .\tests\api-smoke.mjs
node .\tests\browser-smoke.mjs
```

4. 亲自检查以下页面：

   - 总览驾驶舱。
   - 我的待办。
   - 流程中心。
   - 对象与能力。
   - 数字员工。
   - 系统连接器。
   - 审计与证据。

5. 亲自操作：

   - 发起一个样品到转产流程。
   - 通过至少一个节点。
   - 发起一个采购流程，验证重大金额条件节点。
   - 打开一个任务并退回。
   - 模拟运行一个数字员工。
   - 检查审计是否增长。
   - 刷新页面确认 SQLite 数据仍在。

6. 检查移动端 390—500px：

   - 无横向滚动。
   - 导航可打开和关闭。
   - 待办和流程卡片可操作。

7. 检查真伪边界：

   - 是否误称已连接 U9、ERP、DCS。
   - 是否把规则模拟描述成真实大模型。
   - 是否有自动付款、质量放行或 DCS 控制。
   - 是否保存真实敏感数据。

## 输出格式

使用以下结构：

### 一句话结论

“可用于继续验证 / 仅部分可演示 / 不可演示”。

### 实际运行证据

| 项目 | 命令或操作 | 证据 | 通过 |
|---|---|---|---|

### 核心闭环评估

逐项回答：

- 对象是否真实存在且可追溯？
- 流程是否不是只有静态页面？
- 任务是否真实推进实例？
- 条件节点是否根据数据生效？
- 审计是否真实增长？
- 数字员工是否有身份、等级、权限和人工确认？
- mock 与真实连接是否清楚区分？

### 发现的问题

按 P0/P1/P2 排序。每个问题给出文件和复现步骤。

### 真实/模拟/未完成三分表

| 类型 | 内容 | 说明 |
|---|---|---|

### 是否值得继续

从董事长视角判断：

- 对象—流程—任务—审计主线是否成立。
- 是否证明可减少部门定制后端。
- 最大风险是什么。
- 下一阶段最值得投入的三个任务。

不得因为界面漂亮而判定架构成功，也不得因为功能少而忽视核心闭环价值。
