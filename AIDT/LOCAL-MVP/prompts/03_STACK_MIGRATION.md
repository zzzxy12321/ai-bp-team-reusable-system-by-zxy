# 技术栈落地后的迁移提示词

当最终技术栈、部署环境和安全要求已经明确后，使用本提示词。

## 目标

把当前可弃型 AIDT 本地验证版迁移到正式技术栈，保留业务契约、流程语义、权限边界、审计要求和测试证据，不机械复制临时目录结构。

## 开始前必须提供

- 最终前后端技术栈和版本。
- 数据库类型与版本。
- 部署环境：本地机房、私有云、公有云或混合。
- 身份认证和权限体系。
- U9、ERP、DCS、WMS/LIMS等接口资料。
- 安全、审计、备份、等保/质量体系要求。
- 团队规模、交付周期和运维责任。

## 迁移步骤

### 1. 建立对照矩阵

| 当前验证版 | 正式技术栈 | 保留方式 | 风险 |
|---|---|---|---|
| Node 原生 HTTP | 最终后端 | 重写适配层 |  |
| node:sqlite | 最终数据库 | 数据模型/DDL迁移 |  |
| 原生前端 | 最终前端 | 页面重构 |  |
| 自定义状态机 | 工作流/BPM引擎 | 语义映射 |  |
| mock providers | 正式连接器 | adapter实现 |  |
| 本地规则模拟数字员工 | 正式模型/技能平台 | 重写运行时 |  |

### 2. 先冻结业务契约

不得先写页面。先确认：

- 对象类型与字段。
- 对象关系。
- 状态机。
- 业务动作。
- 流程节点。
- 条件表达式。
- 权限数据范围。
- 审计事件。
- 连接器命令和回执。
- 数字员工等级和人工确认点。

### 3. 后端迁移

优先顺序：

1. 身份、组织、角色和数据范围。
2. 对象元模型。
3. 表单/视图元数据。
4. 流程定义、实例和任务。
5. 规则和事件。
6. 审计与证据。
7. 连接器和 mock 替换。
8. 数字员工运行时。

### 4. 前端迁移

- 页面和信息架构可以参考本地MVP。
- 不照搬原生 DOM 操作。
- 保留三类体验：管理配置端、专业工作台、一线移动/扫码端。
- 流程实例、任务和审计必须可互相跳转。

### 5. 数据迁移

- 不迁移演示业务数据到生产。
- 只迁移表结构、字段定义、流程模板和测试样例。
- 建立主数据唯一ID。
- 建立源系统字段映射和数据血缘。
- 所有真实写入先 dry-run，再受控执行。

### 6. 回归测试

保留以下行为测试：

- 正常流程闭环。
- 退回。
- 终止。
- 条件跳转。
- 重复提交幂等。
- 审计增长。
- 权限越界拒绝。
- mock/真实连接状态区分。
- 移动端可用性。

### 7. 停止条件

以下任一条件不满足，不得进入真实系统写回：

- 数据权威矩阵未确认。
- 身份与权限未评审。
- 写入幂等和补偿未实现。
- 审计日志未验证。
- 备份恢复未验证。
- 生产安全和质量责任未明确。

## 最终输出

1. 技术栈映射表。
2. 保留与重写清单。
3. 数据迁移计划。
4. 接口适配计划。
5. 测试计划。
6. 风险登记册。
7. 90天实施路线。
