## 最终目标

在现有“AIDT 本地验证版”基础上，自主完成一晚的加固、扩展、测试和交付。今晚的目标不是生产上线，也不是一次性完成全部13个部门，而是证明：

- AIDT 的对象模型可以支撑跨部门流程。
- 通用流程能力可以被不同业务复用。
- 条件、审批、退回、审计和数字员工边界可以真实运行。
- 最终技术栈未知时，业务契约仍能保持稳定。

你必须先阅读：

1. `task_plan.md`
2. `findings.md`
3. `progress.md`
4. `README.md`
5. `docs/CONTRACTS.md`
6. 产品蓝图：`../AIDT企业业务操作系统-全量功能与流程架构.html`
7. `prompts/00_MASTER_GOAL.md`

## 自主运行规则

- 除非遇到需要真实账号、真实接口授权或用户商业决策的阻塞，否则不要停下来询问。
- 可以作出合理假设，但必须写入 `findings.md`。
- 只修改当前 `AIDT-LOCAL-MVP` 目录内的文件。
- 不执行删除用户数据的操作；如需重置，只能重置本项目的演示数据库。
- 不连接真实 U9、ERP、DCS、钉钉或外部大模型。
- 不发送邮件、消息或产生真实业务副作用。
- 不采真实配方、客户、成本、报价和工艺数据。
- 不因为“技术栈未定”停止。使用可替换接口和适配器把临时技术栈隔离在边界内。

## 工作节奏

### 检查点 1：现状审计

1. 核对当前服务、数据库、API 和前端是否能正常启动。
2. 运行：

```powershell
node --check .\server.mjs
node --check .\public\app.js
node .\tests\api-smoke.mjs
node .\tests\browser-smoke.mjs
```

3. 将任何失败写入 `progress.md` 和 `findings.md`。
4. 不先加新功能，先确保现状测试通过。
5. 修改后端代码后，不能用旧进程测试新代码；先执行 `stop.ps1` 停止旧服务，再执行 `start.ps1` 重启。

### 检查点 2：核心闭环加固

按顺序完成以下事项：

1. 为所有 API 增加输入校验和更明确的错误返回。
2. 增加流程实例详情接口和 UI，能查看：
   - 业务对象与关键字段。
   - 步骤时间线。
   - 当前节点。
   - 已完成任务、处理人、决定、意见和时间。
   - 关联审计记录。
3. 增加任务退回的可验证测试。
4. 增加流程终止的可验证测试。
5. 确保流程动作并发重复提交时不会重复推进；采用事务或状态条件更新。
6. 确保 mock 连接器在界面、API 和文档中都清楚标记为“未真实连接”。

### 检查点 3：可选增强

只有在检查点 1 和 2 全部通过后，才能选择以下最多两个方向：

- 对象详情页和关联实例。
- 简单元数据配置预览，不允许部门随意修改全局对象。
- 流程定义只读可视化，展示条件节点和责任人。
- SLA 逾期升级和任务提醒模拟。
- 数字员工运行结果与流程实例的关联视图。
- 连接器契约检查页。

禁止扩大为完整13部门页面，不得牺牲测试和核心闭环。

### 检查点 4：质量冻结

如果已经连续工作较长时间，或新增功能风险开始上升：

1. 停止新增业务功能。
2. 只修复测试缺陷、可观测性和文档。
3. 重新运行全部测试。
4. 生成明早验收报告。

## 质量要求

- 每个数据写入必须有事务边界。
- 每个流程动作必须写审计。
- 每个客户端错误必须可理解，不能只显示“请求失败”。
- 所有动态插入 HTML 的内容必须转义。
- 不引入 npm 依赖，除非你能证明确有必要且安装稳定。
- 保持 Windows 双击/脚本启动。
- 保持移动端无横向溢出。
- 不把模拟结果写成真实AI能力。

## 中止条件

只有以下情况可以停止并要求用户介入：

1. 需要真实系统账号、网络白名单或接口授权。
2. 需要用户选择法律、财务、质量或安全责任边界。
3. 当前目录数据出现无法安全恢复的损坏。
4. 同一阻塞在三次不同尝试后仍无法解决。

除此之外，持续工作并在磁盘上保存进度。
