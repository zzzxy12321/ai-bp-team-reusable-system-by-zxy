## 关键问题
1. 已解决：业务字段从流程实例迁移到独立 `business_objects`，流程只引用 `object_id`。
2. 已解决：退回、终止、低金额跳过、幂等冲突和并发推进均有自动化测试证据。
3. 已解决：数字员工运行可进入人工确认，并留下确认人、确认时间和审计。
4. 最终技术栈仍未知；继续使用 Node.js 24 + SQLite + 原生前端，不将其包装为最终决策。
5. 不连接真实 U9、ERP、DCS、钉钉或外部大模型。

## 已做决策
| 决策 | 理由 |
|------|------|
| 继续做“可弃型纵向样板”，不做生产底座 | 技术栈未知，目标是验证业务闭环与治理边界 |
| 采用 Node.js 24 原生 HTTP + 内置 SQLite + 原生 HTML/CSS/JS | 本机已具备，零第三方依赖，Windows 可直接启动，离线可跑 |
| 业务能力与基础设施通过接口/适配器分离 | 未来可迁移到 Java、.NET、企业低代码或正式BPM平台 |
| 样板范围锁定为对象、流程、任务、审批、审计、数字员工六个核心能力 | 避免通宵运行无限扩散到14个完整业务系统 |
| U9、ERP、DCS 使用模拟连接器 | 未取得接口、认证和网络授权，不能伪装成真实集成 |
| 所有高风险动作保留人工确认 | 与现有AIDT蓝图的数据和AI治理原则一致 |
| 新建 `business_objects`，流程只保存 `object_id` | 从数据层落实“一个现实实体一个主对象” |
| 只选“流程详情+证据”和“对象详情+关联流程”两个增强项 | 直接强化验收主链，不扩展部门页面群 |
