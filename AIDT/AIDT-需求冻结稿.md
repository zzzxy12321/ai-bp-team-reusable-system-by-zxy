# AIDT 企业业务操作系统：需求冻结稿

> 版本：V1.0  
> 整理日期：2026-10-29

> 用途：把产品意图、范围、技术边界和验收口径重新收敛到一份可评审文档。本文是需求基线，不等同于已经确认的最终生产技术栈。

## 🎯 一句话定义

AIDT 是普赛达的企业业务操作系统。它让研发、实验室、生产、质量、设备、EHS、供应链、仓储、交付、客户、财务、人力、法务、项目和经营管理在同一套业务对象、权限、流程、证据和数字员工治理框架上协同；同时保留 U9、ERP、DCS 等专业系统各自的数据权威。

产品的核心竞争力不是“能画多少流程”，而是：

1. 同一套标准能力能否被多个部门复用。
2. 一个现实实体是否只有一个主对象。
3. 跨部门流程能否稳定闭环并留下审计证据。
4. 数字员工是否在明确授权和人工确认边界内参与执行。

## 🧠 不可破坏的架构原则

### 对象与流程

1. **对象先行**：客户、供应商、物料、实验、批次、偏差、合同等现实实体只能有一个主对象。
2. **流程引用对象**：流程实例只保存 `object_id` 或稳定引用，不复制业务字段。
3. **流程只负责编排**：流程定义“在什么条件下、由谁做什么、失败怎么办”，不是系统唯一数据模型。
4. **状态、动作、事件分层**：业务对象发生状态变化后发布事件，再由规则、流程、任务、通知、接口或数字员工响应。

### 数据权威

| 系统 | 权威范围 | AIDT 的责任 |
|---|---|---|
| U9 | 财务凭证、总账、应收应付、成本及部分库存账 | 读取、分析、预算与费用前置控制；写入必须走受控命令接口 |
| ERP | 客户订单、物料需求、计划、工单、采购交易、库存业务 | 跨部门协同、异常、变更、交付；通过标准 API 或事件交互 |
| DCS/PLC | 实时工艺参数、设备状态、联锁、报警 | 只读报警摘要、批次关联、异常处置和证据；不得替代安全控制 |
| AIDT | 项目、任务、审批、研发、实验、质量异常、变更、文档、知识、AI 执行记录 | 业务主账本、流程账本、证据账本和统一业务入口 |
| 钉钉/HR | 组织身份、消息、移动入口 | SSO、待办、通知、移动审批；不保存业务权威状态 |

硬规则：

- 禁止直接写 U9、ERP、DCS 业务数据库。
- 跨系统写入必须经过受控命令接口、幂等键、审批证据和回执。
- DCS 高频参数进入时序存储，不进入普通业务表。
- 外部系统不可用时必须有补偿、对账和人工接管方案。

### 能力复用与配置治理

目标配置结构为“80/15/5”：

- 80% 通过标准能力包和模板配置完成。
- 15% 通过参数、规则、字段和页面布局调整完成。
- 5% 由平台团队进行受控扩展。

配置分级：

| 级别 | 配置内容 | 责任人 | 审批要求 |
|---|---|---|---|
| L1 | 个人视图、提醒、快捷操作、筛选条件 | 员工/班组长 | 不需要 |
| L2 | 部门字段、节点、审批人、SLA、通知、报表 | 部门负责人/FDE | 平台审核 |
| L3 | 对象、状态机、跨部门规则、接口映射 | 领域产品经理+平台团队 | 需要 |
| L4 | 身份、数据模型、连接器、安全、审计 | 核心平台团队 | 架构委员会 |

正式系统必须具备对象与流程的版本、测试、发布、影响分析、回滚和运行监控。

## 🔁 四个样板业务流程

### A. 客户样品到研发转产

客户需求 → 立项评审 → 配方与实验 → 测试判定 → 试产评审 → 转产发布。

关键证据：

- 客户原始需求与技术确认版本。
- 配方版本、实验记录和原始数据。
- 样品去向与客户反馈。
- 试产、质量评价与转产审批。

### B. DCS 越限到批次异常、处置和 CAPA

DCS 报警 → 关联工单与批次 → 班组现场确认 → 工艺质量联合评审 → 偏差/CAPA → 受控回写 ERP/U9。

硬边界：

- 数字员工不得修改 DCS 控制参数。
- 不得绕过联锁或替代现场安全确认。
- AIDT 可以汇总报警、关联批次、生成建议和保存证据。

### C. 请购到采购、到货检验和付款

需求部门请购 → 预算与采购策略 → 合同/订单 → 到货检验 → 三单匹配 → 付款审批 → 供应商评价。

关键规则：

- 订单、验收和发票必须匹配。
- 付款由授权财务人员审批，数字员工不得直接付款。
- 高金额采购进入重大审批条件节点。

### D. 客诉到批次追溯、处置、改进和回访

客诉受理 → 批次与同批去向追溯 → 研发质量联合调查 → 客户处置方案 → CAPA 与体系更新 → 回访关闭。

## 🤖 数字员工要求

数字员工必须具有：

- 独立身份，不共用真人账号。
- 所属部门、业务负责人和技术负责人。
- 独立数据范围、工具范围、模型范围和预算。
- A0—A4 执行等级。
- 高风险动作的人工确认点。
- 输入、工具、模型、输出、审批、回执、成本和错误记录。
- 运行限制、熔断条件、紧急停止开关和退役机制。

执行等级：

| 等级 | 行为 | 人工边界 |
|---|---|---|
| A0 | 只分析、检索、判断和生成建议 | 所有决定由人做出 |
| A1 | 生成报告、邮件、表单草稿 | 发送或提交前人工确认 |
| A2 | 创建任务、发送提醒、生成报表 | 仅限可逆动作 |
| A3 | 在金额、数量和规则范围内自动执行 | 超限、异常或高风险转人工 |
| A4 | 低风险、可逆、非安全关键流程自动闭环 | 必须可监控、可补偿、可停止 |

永久保留人工签认的场景：

- 财务付款
- 质量放行
- 配方变更
- 安全联锁
- 高风险 EHS 作业
- 对外合同承诺
- 客户重大赔付

## 🔌 集成要求

每个连接器至少应支持：

- 认证与授权、密钥和证书轮换。
- 字段、编码、单位、日期、枚举和主数据映射。
- 幂等控制。
- 超时、重试、熔断、死信和人工补偿。
- 调用量、延迟、失败率、积压和业务异常监控。
- 逐日或按批次对账。
- 版本管理和契约测试。

接口分为：

1. 查询接口：分页、增量、权限和来源标识。
2. 命令接口：幂等、审批凭证和业务回执。
3. 事件接口：状态变化主动推送、去重和重放保护。

## 🔐 非功能与治理要求

### 安全

- 正式身份认证、SSO、会话管理和多因素认证。
- RBAC + ABAC，覆盖组织、项目、字段、动作和数据级别。
- 配置访问最小权限和敏感字段隔离。
- 审计拒绝访问和越权尝试。
- 附件病毒扫描、访问控制和数据留存。
- 核心商密数据不得进入公共模型或公共演示环境。

### 审计与证据

- 记录操作者、时间、对象、旧值/新值、原因、请求来源和证据引用。
- 关键审计记录不可静默修改或删除。
- 流程、任务、对象和数字员工运行可互相跳转追溯。
- 外部写入保存审批凭证、幂等键、接口回执和补偿结果。

### 可用性与运维

- 生产环境必须定义 SLA、RTO、RPO、备份频率和恢复演练。
- 必须具备监控、告警、日志、链路追踪和容量规划。
- 必须具备数据库迁移、版本发布、回滚和应急切换。
- 关键流程不得因单节点故障丢失任务或重复执行。

### 性能与数据规模

- 列表和审计查询必须分页、筛选并可使用索引。
- 高频 DCS 数据使用时序存储，业务库只保留摘要和关键节点。
- 大批量导入必须提供预校验、失败行回执和可回滚机制。

## ✅ 验收标准

### 业务验收

- 至少三条业务链从发起走到完成。
- 至少一个退回和一个终止场景有自动化证据。
- 至少一个条件节点能按对象数据自动进入或跳过。
- 任务动作会推进实例、生成下一任务并写审计。
- 对象、流程、任务、审计和数字员工运行可以互相追溯。

### 技术验收

- API 契约、数据库迁移和权限测试可重复执行。
- 浏览器覆盖桌面和移动端关键路径。
- 重复提交、并发推进和连接器重试不会产生重复业务结果。
- Mock、已连接、未连接和故障状态必须明确区分。
- 备份恢复、审计不可篡改和越权拒绝经过验证。

### 产品验收

- 标准能力复用率目标不低于 80%。
- 部门定制后端数量接近 0。
- 流程平均周期、人工触点、重复录入次数相对基线持续下降。
- 试点部门周活跃率和流程线上完成率达到约定目标。

## 🚫 明确不做或不得直接做

- 不把 AIDT 做成只能画流程、不能管理对象和数据的工具。
- 不为每个部门独立建设后端。
- 不用页面数量代替业务闭环和能力复用。
- 不让数字员工控制 DCS/PLC、直接付款、直接质量放行或修改批准配方。
- 不把 mock 结果描述为真实系统或真实 AI 结论。
- 不在未授权时连接真实系统、发送真实消息或产生真实付款。
- 不把当前本地 SQLite 演示库直接当作生产数据库。

## ❓ 尚待拍板的关键事项

以下事项会实质影响技术栈和工期，当前文档没有足够信息替用户做最终决定：

1. 最终部署环境：本地机房、私有云、公有云或混合云。
2. 企业身份源：钉钉、AD/LDAP、U9/ERP 用户或其他 IdP。
3. 等保、数据分级、审计留存和电子签名要求。
4. U9、ERP、DCS、WMS、LIMS 的实际接口、认证方式和网络拓扑。
5. 第一阶段试点部门和三条样板流程的最终口径。
6. 研发、实施、测试、运维和安全团队规模。
7. 是否采购成熟 BPM、文档、电子签或低代码产品。
8. 生产环境 SLA、RTO、RPO 和最大用户/数据量。
9. 多法人、多工厂、多组织是否从第一期就需要隔离。
10. 12—18 个月路线是否按管理层的业务优先级和预算重新排期。
